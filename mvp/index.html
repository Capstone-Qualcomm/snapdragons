Run one AI agent across a cluster of small boards.

A conductor board breaks each goal into steps and hands them to worker boards. Adding a board adds capacity, and losing a board loses no work.

How it works

  1. 01A goal comes inFor example, "get the Qualcomm demo ready by Thursday."
  2. 02The conductor splits itFetch Slack, read Notion, run tests, draft the update.
  3. 03Free boards pick up stepsEach step goes to whichever board has an open slot, so many tasks run at once.
  4. 04Failures are absorbedBoards send heartbeats and checkpoints. If one goes quiet, its steps resume on another board.
Concurrency

Steps from different tasks share the same boards.

Q-02 is busy with Slack for task T01, so when T03 also needs Slack, the conductor sends that fetch to Q-04. Q-03 needs Q-02's Slack result before it can summarize T01, so it waits. Every other board keeps working.

Scaling and reliability

More boards, more capacity. Fewer boards, same result.

Resume from checkpoint

Q-04 saves progress after every step. It dies during test 2, so Q-06 starts at test 2 instead of redoing the diff, lint and test 1.

Conductor fails, majority elects

Conductor is a role, not a fixed board. When Q-01 goes quiet the rest vote, and taking over needs 4 of 6 votes, so two conductors never run at once.

External actions run once

Before a Slack post or PR comment runs, its key is written to the shared log. A retry after failover finds the key and skips.
